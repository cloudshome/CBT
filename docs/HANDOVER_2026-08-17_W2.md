## 2. What was built

### Zone overlays — `web/chart_data.py` + `web/app.py`

The engine has always computed Smart-Money-Concept structure
(`engine/structure.MarketStructure.as_dict`: order blocks, fair-value gaps,
buyside/sellside liquidity, sweep detection, premium/discount dealing range),
but the chart only ever showed it as text. Now:

- **`web/chart_data._zones(payload)`** reads `payload["snapshot"]["structure"]`
  and returns JSON-safe bands/lines:
  - `order_blocks` (top/bottom, side, tested/broken),
  - `fvgs` (top/bottom, side, filled),
  - `liquidity` (buyside/sellside price levels),
  - `sweep` (level, side, recovered),
  - `dealing_range` (top/bottom, premium/discount zone).
  Every value funnels through `_num`, so a NumPy scalar can never blank the
  chart (the same class of bug that broke `/api/candles` originally).
- **`build_chart`** now carries `"zones"` in its payload; `GET /api/chart`
  returns it unchanged.
- **UI:** a **"Zones (OB / FVG / liq)"** toggle (on by default) in the chart
  toolbar. `drawZones(candle, zones)` draws each band as its top + bottom
  horizontal price lines (Lightweight Charts v4 has no rectangle primitive,
  so a shared-colour pair reads as a band): bullish green, bearish red,
  **dashed when tested/broken/filled** so a dead zone is visibly different
  from a fresh one. Liquidity = single dashed lines; a sweep = a highlighted
  line (amber when recovered, red when it failed); the dealing range = two
  blue lines labelled premium/discount.

### Replay mode — `web/app.py`

- A **▶ Replay** button + speed toggle (1×–4×) in the chart toolbar.
- `toggleReplay` disposes the live workspace, builds a fresh price pane, and
  walks the **already-loaded** candles bar-by-bar via `series.setData` on a
  growing slice — no live data, no network, no new endpoint.
- The chart head is replaced with an unmissable
  **"▶ REPLAY — historical playback, not live"** badge plus the current bar
  index and timestamp, so a replay can never be read as live or paper
  evidence. Stopping (or reaching the end) restores the full workspace.

### Tests

- `tests/test_chart_data.py` (new, 5 tests) — the `_zones` transform: 1:1
  structure→bands, top/bottom normalisation, NumPy-scalar safety, empty-when-
  no-structure, and `build_chart` carrying the key.
- `tests/test_workstation_js.py` (+3 W2 tests) — `drawZones` renders every zone
  kind as price lines (incl. the dashed "done" tag), replay labels itself
  immediately and stops at the end, and chart reload safely stops replay before
  redrawing.
- Consolidation regression tests also pin W1 fail-closed persistence, inline
  reload restoration, unknown/stalled observed-rate states, and explicit
  per-setup no-edge reporting while other setup gaps remain.

Full consolidated suite: **1030 passed / 1 skipped**; compile, dashboard-JS
syntax, offline engine smoke and the clean-install wheel gate also pass.

## 3. Honest flags (per §0a)

- **No real browser was opened** (none is installable in this sandbox). The
  zone drawing and replay were verified through the node/jsdom harness
  (which runs the *real* dashboard JS against a stubbed chart library), the
  Flask test client (`/api/chart` returns `zones`; the page renders the new
  controls), and a direct in-process `build_chart` run on real engine
  structure output. The pixel-level look of the bands was not eyeballed.
- **Zones are drawn as paired price lines, not filled rectangles.** Lightweight
  Charts v4 has no rectangle primitive (v5 adds one, but the vendored build is
  v4.2.3 and switching is a larger change). The top/bottom line pair is the
  honest equivalent; if filled rectangles matter visually, that is a v5
  upgrade decision, not a bug.
- **Replay reuses the chart's own candles** (300 bars via `/api/chart`), not
  the full Parquet store. It is a *workstation playback*, not a deep-history
  scrubbing tool — for that, use the store/simulator. It cannot be confused
  with live or paper evidence because the head is overwritten with a REPLAY
  badge and it never writes anything.
- **Drawing tools and live streaming are not here** (see §4). I did not fake
  them; the remaining W2 items are genuinely interactive/streaming work.

## 4. What is deliberately not here (remaining W2)

- **Live streaming** (item 1) — push candle updates over SSE/WebSocket from
  `data/ws_client.py` and call `series.update()` instead of redrawing. Needs a
  server-side stream + reconnect semantics (the P18.3 SSE layer is the
  natural foundation).
- **Drawing tools** (item 2) — interactive trendlines/rays/boxes with
  mouse placement, persisted per symbol/timeframe (localStorage to start),
  attachable to the scan record. Needs chart mouse-event handling + a
  persistence shape.

No threshold moved, no order path added, no new capability beyond display.
