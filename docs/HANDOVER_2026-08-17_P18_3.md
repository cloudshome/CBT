## 1. What the roadmap asked for

From `ROADMAP.md` §P18.3:

> - Move long jobs (backfill, backtest, simulator, evidence build) behind a
>   persisted job queue with status, progress, cancel, and audit history.
> - Server-sent events for job progress and live health/candle notifications;
>   reconnect resumes from the last event rather than restarting work.
> - Only allow-listed jobs and validated arguments; no shell-command endpoint.
> - W1 guided “Build my evidence” flow uses this layer.

> **Done when:** closing a browser does not kill a job, duplicate clicks do not
> start duplicate runs, and progress survives reconnect/restart.

All of it ships, except the live *health/candle* SSE stream (that is Priority 1
in `HANDOVER.md` — "Live streaming" over `data/ws_client.py`) — see §5 for the
honest boundary. Job-progress SSE is complete.

## 2. What was built

### `web/jobs.py` (new, stdlib only)

A persisted background-job queue with one in-process worker.

- **`JobManager`** — `submit / get / list_jobs / tail / request_cancel /
  events / start / stop`. Every DB access opens its own `SignalDB` connection
  (WAL + busy_timeout), so the worker thread and Flask request threads share
  the `jobs` table safely.
- **`jobs` table** in `data/database.py` — `job_id`, `kind`, `params_json`,
  `params_hash`, `status`, timestamps, `step_index`/`step_total`, `phase`,
  `exit_code`, `error`, `cancel_requested`, `log_path`. The full output log is
  appended to `data/job_logs/<job_id>.log` (gitignored); only a tail is loaded
  into memory for status/SSE.
- **Allow-list only.** `JOB_KINDS` declares the runnable kinds (backfill,
  backtest, simulator, scorecard, derivatives collect, cross collect) with
  their validated `--flag` inputs; `build_argv` validates exactly like
  `web/command_center` so the browser Command Center and the queue share one
  allow-list. An unknown kind or a bad parameter raises `JobError` *before*
  anything is persisted. No shell string is ever executed — it is always
  `python main.py <validated argv>` via `subprocess.Popen` with an unbuffered
  pipe.
- **Composite jobs.** `COMPOSITE_JOBS["evidence"]` chains Backfill → Backtest
  → Simulator → Scorecard as one submission, each step reporting its own
  phase and `step_index/step_total`. This is the backbone the W1 flow sits on.
- **Deduplication.** `params_hash = sha256(kind + canonical params)`. A
  submission whose hash matches a still-`queued`/`running` job returns the
  existing `job_id` with `created: false` instead of starting a second run. A
  *finished* job is legitimately re-runnable.
- **Cancel.** `request_cancel` cancels a queued job outright and requests
  cancellation of a running one (the worker checks the flag between output
  lines, then SIGTERM→SIGKILL). Terminal jobs refuse cancellation with
  `JobError`.
- **Restart safety.** The worker adopts any orphaned `running` row at boot and
  marks it `interrupted` (with a note to resubmit) — it never silently
  re-runs a half-done job, nor leaves it lying.

### `/api/v1/jobs` (v1-native, in `web/app.py`)

- `GET /api/v1/jobs` — list jobs (newest first, `?status=`, `?limit=`), plus
  the published `kinds`.
- `POST /api/v1/jobs` — submit `{kind, params}`. Returns `{job, created,
  duplicate}` in the one v1 envelope. Role: **operator**.
- `GET /api/v1/jobs/<job_id>` — one job + log tail. Role: viewer.
- `POST /api/v1/jobs/<job_id>/cancel` — request cancellation. Role: operator.
- `GET /api/v1/jobs/<job_id>/events` — `text/event-stream`; every frame is a
  full snapshot of the persisted state (`id: <job>:<status>:…`, `event: job`),
  so a reconnect resumes from the last persisted event — there is no in-memory
  sequence to lose. Emits one terminal frame, then closes.

New typed error codes: `JOB_NOT_FOUND` (404) and `JOB_NOT_CANCELLABLE` (409).
The routes are declared in `apiv1.NATIVE_ROUTES` so the role gate and the
published `/api/v1/routes` catalog stay in sync; the gate now matches
`/jobs/<job_id>` path templates against concrete paths (fails closed to
`operator` if ever undeclared).

### UI (clickable, per the owner's standing request)

- The **Command center** tab gained a **Background jobs** panel: list of jobs
  with status badges, cancel buttons, and a live-output pane that streams via
  `EventSource` (closing the tab/browser does not stop the job).
- Slow (`🟠`) commands in the Command center now **submit a job** instead of
  blocking behind one POST; fast/read commands still run synchronously.
- The **Evidence** tab gained a one-click **"Build my evidence"** button that
  submits the composite 4-step job.

### Tests — `tests/test_jobs.py` (23 tests)

Persistence + worker, allow-list/validation refusal, dedup (identical params
vs. different params), cancel (queued / running / finished), restart adoption,
the v1 envelope + typed codes, the operator/viewer role split, SSE framing,
and the route catalog. The runner is injectable so tests never spawn a real
subprocess.

## 3. What the "done when" maps to

| "Done when" | Where |
|---|---|
| closing a browser does not kill a job | the job runs in the server process (worker thread), not in the request; `tests/test_jobs.py::test_job_runs_outside_the_calling_thread` |
| duplicate clicks do not start duplicate runs | `params_hash` natural dedup + `tests/…::test_duplicate_submission_returns_existing_job` |
| progress survives reconnect/restart | state persisted in `jobs` + `data/job_logs/`; SSE frames are full snapshots; restart adoption marks orphans `interrupted` |

## 4. Honest flags (per §0a)

- **No real browser was opened.** The UI was verified through the jsdom harness
  (`tests/test_dashboard_js.py`, `tests/test_workstation_js.py`) and the Flask
  test client, plus a live `curl` smoke test against the real server (job
  submitted, ran in DEMO mode, streamed its log, SSE framed and closed). The
  click path was not eyeballed by a human in a browser.
- **Within-step progress is whatever the command prints.** `backfill`/
  `simulator`/`backtest` print a final summary, not a per-page ticker, so a
  single-step job's live progress is "running → done" plus any lines it emits.
  The *step* progress (1/4 → 4/4) is real for the `evidence` composite. If
  finer progress matters, the commands themselves need a progress callback —
  out of scope here, and I did not fake a percentage to look better.
- **In-process worker, single job at a time.** Chosen deliberately: one Hub
  owns DB/workers (per the topology decision), long jobs share the Parquet
  store and SQLite, and running several at once would just thrash. The cost is
  that a *server* restart kills the running subprocess — the row is marked
  `interrupted` (recoverable, resubmit), not lost, but it is not checkpointed
  mid-run. A separate `sky-jobs` systemd unit (like the existing scan/paper
  units) would survive a dashboard restart and is the natural next hardening
  if that matters.
- **The idle worker *blocks*, it never polls.** An early version polled the
  `jobs` table on a fixed interval; because every `make_app()` constructs a
  `JobManager`, the test suite leaked one polling thread per app — each
  re-opening its (soon-deleted) `tmp_path` database every interval — which
  pushed CI past its 10-minute budget. The worker now `Event.wait()`s and
  wakes only on submit/cancel; a regression test pins "no DB opens while
  idle".
- **Dedup window is live jobs only.** Two identical clicks 10 minutes apart
  (first already finished) intentionally start a new run — that is a new
  request, not a double-click.
- **`evidence` uses default parameters** (`BTCUSDT/1m` backfill, default
  rounds). The W1 follow-up should add per-symbol/per-timeframe selection and
  the "projected unlock: ~N more simulator rounds" estimate, which is a W1
  feature, not P18.3.

## 5. What is deliberately not here

- **Live candle/health SSE** (Priority 1 in `HANDOVER.md`) is separate: it
  pushes market data from `data/ws_client.py`, not job progress.
- **The W1 guided flow's projection/UX** ("at this rate ~N more rounds") — W1
  builds on `submit("evidence", …)`, it is not built here.
- **No new capability.** The job layer runs the *same* allow-listed commands
  the Command Center already ran; it cannot place an exchange order (none
  exists anywhere in SKY), cannot loosen the risk gate, and adds no trading
  path.
