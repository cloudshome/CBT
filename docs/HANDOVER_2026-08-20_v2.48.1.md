# PWA Cache and Test-Environment Reliability — v2.48.1

**Shipped:** 2026-08-20 · branch `arena/01a01e1a-sky` · version **2.48.1**

---

## Summary

This patch closes two reliability gaps found while establishing a clean v2.48.0 baseline:

1. the application was v2.48.0 while the service worker still owned `sky-shell-v2.47.0`; and
2. two `sky-agent` CLI tests escaped the active Python environment by invoking ambient `python` from a relative working directory.

No trading computation, threshold, evidence population, risk rule, graduation rule, API capability, or order boundary changed.

---

## Delivered

### 1. PWA release cache rollover

- Advanced `web/static/sw.js` to `sky-shell-v2.48.1`.
- This changes the service-worker source, causing installed clients to run install/activate and retire the previous release precache.
- The existing privacy boundary is unchanged: `/api/*`, authentication, SSE, mutations, and private payloads remain network-only and never enter CacheStorage.

### 2. Release-version invariant

`tests/test_pwa.py::test_release_versions_and_pwa_cache_stay_in_lockstep` now requires exact agreement between:

- `config.VERSION`;
- `[project].version` in `pyproject.toml`; and
- the `sky-shell-v...` suffix in `web/static/sw.js`.

The regression was proven red against the inherited state (`PWA cache 2.47.0 != application 2.48.0`) before the fix. Future release bumps that omit the installed-PWA cache now fail CI.

### 3. Hermetic agent CLI tests

The two subprocess tests in `tests/test_sky_agent.py` now use:

- `sys.executable`, so the child process retains the interpreter/dependencies running pytest; and
- an absolute `main.py` path, so behavior does not depend on the caller's current directory.

This matches the pattern already used by the rest of SKY's CLI test suite. Before the fix, `.venv/bin/python -m pytest tests/ -q` reached 1280 passing tests but these two children called system `python` and falsely reported that installed dependencies were missing.
