# Handover — 2026-08-21 · v2.55.0 — T6: focused pages + mobile sections

**T1–T6 is now complete: the terminal is a product, not a pile of panels.**
Every nav area is a focused page — an identity header with purpose and a
compact sub-section switcher, exactly **one section visible at a time** instead
of the old five-stacked-cards shell — and on phones there is a four-section
thumb bar (Markets / Chart / Positions / AI) with the paper ticket opening as
a **full-screen sheet that re-reads the risk gate fresh**.

**No new capability.** Presentation layer only: panels, endpoints, loaders
and permissions are untouched; `switchSub` drives the *same* `onTabShown()`
loaders the old `switchTab()` used. Zero new endpoints, no threshold moved,
no exchange-order path.

## What shipped

### Focused pages (`#areaHead`, one section per area)

- Each legacy area gets a header (title + one-line purpose) and, where the
  area has more than one section, an `.areasub` switcher:
  - **Markets** — Overview / Market radar / Intelligence
  - **Portfolio** — Positions (default) / Decisions / Risk centre / Weekly review
  - **Journal** — Journal (single section: no switcher, header only)
  - **Evidence** — Evidence / Learning
  - **System** — Data health / Connections / Hub & agent / Command centre /
    Modules (the roadmap's advanced tools, kept under System)
- Exactly one `.tabpanel` active at a time — `navTo('portfolio')` shows
  Positions, not a stack. Sub-choice persists per browser
  (`sky.sub.<area>`), a removed/renamed section falls back to the area
  default, and the hash is `#<section>` so any section is deep-linkable.
- **Every old `switchTab(name)` call keeps working** — the wrapper maps a
  section name to its owning focused page (`switchTab('learn')` → Evidence →
  Learning). Quickbar, coach links, W-features untouched.
- **`#risk`-style deep links**: init resolves a section hash to its owning
  page (`#risk` → Portfolio · Risk centre). No hash and no remembered view
  still lands on Home (T5); a remembered area/section view restores itself.
- `render()`'s panel re-apply can **never navigate** the user: it re-applies
  the current focused section only (`applyNavPanels`), it no longer calls the
  old `switchTab(_activeTab)` rewrite that could yank the view on a 30 s
  refresh. `NAV_TABS` is gone — `AREA_SUBS` is the single mapping.

### Mobile (≤760px)

- **Four-section bottom bar** (`#mobileNav`): Markets → Markets page,
  Chart → terminal, Positions → terminal with the positions bottom tab,
  AI → Copilot drawer. Active state tracked (`_mobileSec`): it clears when
  you move off (another bottom tab, closing the drawer, another area). The
  full seven-area nav stays available at the top — nothing is amputated for
  the small screens; page gets `padding-bottom` so the bar never covers
  content; safe-area inset respected.
- **Paper ticket as a full-screen sheet**: `🎫 Ticket` in the chart toolbar
  (`mobile-only`); `.t-order` slides in fixed over everything, backdrop tap or
  ✕ closes, leaving the Trade area closes it too. On open it issues **fresh
  `/api/risk` reads** (`loadRiskChip` + `loadTicketGate`) — the gate verdict
  next to Confirm is current — and the T3 confirm still re-reads the gate on
  the server immediately before enrolling (unchanged).

## Honest boundaries (unchanged)

- "Focused" means **header + one-section-at-a-time composition** — the
  section panels themselves are the existing P13–W4 surfaces, intentionally
  not rewritten (all their tests still pass untouched).
- The mobile bar is a §12 "four primary sections" quick nav; the top nav
  remains for the full app. Approval online-only is unchanged: Confirm is a
  server action (T3), the sheet merely keeps its gate read fresh.
- **No real browser in this sandbox** — proven with the node harness (14 new
  tests), the Flask test client, `node --check` on the served script, and
  `curl` on a running dev server. Real-device visual QA (drawer, sheet, drag
  gestures, the T3 loop, T5 hero) stays the open T1–T6 item; thumb-target
  review should happen on a real phone.
