## What shipped

### One coherent, validated run

The Evidence tab now selects asset, timeframe, market, history range, backtest
bars and simulator rounds. `web/jobs.py::COMPOSITE_JOBS["evidence"]` maps those
values into:

1. Backfill — `symbol`, `tf`, `market`, `since`
2. Backtest — `symbol`, `tf`, `bars`
3. Simulator — selected `symbol` as `symbols`, plus `tf`, `rounds`
4. Scorecard — the database book

Composite inputs are closed and normalized before persistence. Unknown fields,
unsupported choices, non-positive integers and oversized values fail before a
job row exists. Every expanded child is checked again through the same
allow-list before execution. Explicit defaults and `{}` deduplicate as the same
live request.

### Progress where the user works

The Evidence tab no longer jumps to Command center. It shows the persisted job
phase, actual four-step progress, and an SSE log tail inline. Reloading the page
finds and reconnects to the active evidence job; closing the page still does not
stop it.

### Honest projected gap and result

`JobManager.evidence_guidance()` combines the primary-setup sample gaps with the
round additions printed by recent successful simulator/evidence jobs.

- No observed run: projection is `unknown`; it does not invent a rate.
- Positive observed pace: `~N more rounds`, based on aggregate recent additions.
- Zero unique additions while a gap remains: `stalled`.
- Targets complete: zero rounds.

The UI always states that this is a rough aggregate estimate: unique-window
deduplication can slow future rounds, and additions can include non-primary
setups.

The result vocabulary is deliberately conservative:

- `unmeasured` — no primary setup measurements;
- `incomplete` — sample targets not met, so no edge inference;
- `no_edge` — targets met but net expectancy is absent/non-positive;
- `edge_measured` — every primary setup passes sample counts and positive net
  expectancy, while graduation/discipline/risk gates still remain separate;
- `mixed` — no blanket edge claim is justified.

There is no parameter auto-tuning. A no-edge result explicitly says not to tune
parameters merely to turn the result green.

## Honest boundary

The projection is an estimate, not a promise or profitability forecast. It is
based on aggregate logged additions because historical rows do not record a
per-primary-setup yield for each simulator round. The UI labels that limitation.
No real market evidence was generated as part of this code change, and passing
software tests does not prove a strategy is profitable.
