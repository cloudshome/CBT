The review followed the P12.11 → P12.15 thread. Those five milestones walked

that reads **decided** paper trades:

| Milestone | Surface isolated |
|---|---|
| P12.11 | calibration keys, setup-proven gate |
| P12.13 | global graduation performance gate |
| P12.14 | graduation discipline / compliance |
| P12.15 | every live risk control (loss limits, drawdown ladder, Kelly, MC, MAE/MFE, scorecard) |

Every one of those reads the **closed** book. Nobody had asked the same
question of the **open** book — the positions the desk is carrying *right
now*. The answer was that the open book had no boundary at all:

```sql
-- open_exposure(), active_paper_trades() — before P12.16
WHERE status IN ('WAITING_ENTRY','OPEN')     -- no sim_key filter, no source_key filter
```

This is the mirror image of the P12.15 finding, and it is arguably worse:
P12.15's failures were mostly *fail-open* (a research win masking a real loss).
The open-book failures are mostly **fail-closed** — the system refusing real
trades the desk is entitled to take, which is the failure mode most likely to
be misread as "the engine is broken" and worked around by hand.

## 2. What was measured (probe cases A–F, on `731119d`)

### A. The portfolio veto blocked a real trade against a flat book

One open `dukascopy:spot:bid` BTCUSDT row — a research import, not a position
the desk holds:

```
portfolio_veto(db, "BTCUSDT", "BUY")
  → allowed=False
    "Portfolio veto: BUY already open in the crypto risk bucket (1 open)
     — correlated exposure, not a second edge"
```

The live crypto bucket was flat. P12.13 settled that research evidence may
neither unlock nor block the live desk; on the open side it blocked.

### B. Research positions consumed the live bucket's risk cap

Two research positions read `n_open=2`, `planned_risk_pct=1.0` — exactly
`CRYPTO_BUCKET_MAX_TRADES` and `MAX_CRYPTO_EXPOSURE_RISK_PCT`. The live bucket
was reported full and at its risk ceiling while holding nothing.

### C. Interrupted simulator runs leaked permanent live exposure

`data/simulator.py` inserts each walk-forward sample with `status='OPEN'` and
closes it later in the same pass. That is fine when the pass completes. If it
is interrupted, the `sim_key IS NOT NULL` rows stay `OPEN` forever and — before
this fix — read as live positions holding live risk slots. This is a latent
trap: it costs nothing until the day someone Ctrl-Cs a `simulate` run, and then
silently vetoes live trades with no visible cause.

### D. The paper runner polled research and simulator rows as live work

`PaperRunner._process_trade()` fetches candles via `self.client` — the
**canonical live** market-data client — using only the row's `symbol` and
`timeframe`. Handing it a `dukascopy:spot:bid` XAUUSD row means pricing a
Dukascopy bid-side setup against live Binance candles, and it can then
`open_paper_trade()` / `close_paper_trade()` / journal that row. A research
import could thereby write itself into the live book's history under a
research source key, which is precisely what P12.11 exists to prevent.

### E. Reported exposure overstated the book

A desk carrying **1** live position reported **6** open paper trades through
`open_exposure()` — the CLI, `agent ask "exposure"`, the agent briefing, the
watchdog agent's alerting and the dashboard all read that number.

### F. Control

A canonical-only open book, including legacy NULL-provenance rows, must behave
exactly as before: bucket full at 2, duplicate direction vetoed.

## 3. The fix

**One definition, many surfaces** (invariant #10), mirroring P12.15:

```python
SignalDB.live_open_rows(symbol=None)   # THE live open book
    status IN ('WAITING_ENTRY','OPEN')      # carried right now
    AND sim_key IS NULL                     # not machine walk-forward samples
    AND COALESCE(source_key,'') = ''        # canonical live; legacy NULL kept
```

`_open_book_clause(conn, alias="")` supplies the same predicate as a literal
SQL fragment (both halves are constants, so nothing needs binding) for the
`open_exposure()` UNION, which cannot easily thread bound arguments.

Call sites now reading the live open book:

| Surface | Path |
|---|---|
| Portfolio veto + bucket risk cap | `brain/portfolio.py` → `db.open_exposure()` |
| Paper runner polling set | `data/paper_trading.py` → `db.active_paper_trades()` |
| Watchdog agent | `brain/agents.py` (raw SQL → `db.live_open_rows()`) |
| Desk / briefing / `agent ask` exposure | `brain/agent.py` → `db.open_exposure()` |
| CLI + dashboard paper stats | `paper_trade_stats()["overall"]["live_open"]` |

Deliberate non-changes:

* **The approved-scan half of `open_exposure()` is untouched.** A scan awaiting
  enrolment has no provenance columns yet and represents a live intention.
* **`paper_trade_stats()` keeps its broad totals.** It is the store inventory
  report — how a reviewer sees that research and simulator rows exist at all.
  It gains `live_open` alongside, and the surfaces that state exposure as a
  *fact* print the live number when the two differ.
* **`active_paper_trades(include_all_sources=True)`** restores the unfiltered
  read for maintenance and inspection callers.
* **No threshold moved in either direction** — not `CRYPTO_BUCKET_MAX_TRADES`,
  not `MAX_CRYPTO_EXPOSURE_RISK_PCT`, not the loss limits, drawdown ladder or
  graduation bar.
