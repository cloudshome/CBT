## 1. The problem this closes

The scorecard (P12.3/P12.6/P12.3.3) reports the numbers, P12.4
(`data/quality_score.py`) judges whether the curve is robust, and the
calibrator (`brain/calibrator.py`) turns a setup's observed expectancy into
the confidence multiplier the engine actually applies. Before P12.5 the
calibrator trusted **gross expectancy alone**:

    mult = clamp(1 + E_gross × gain, min, max)

So a fragile, weakly-sampled, regime-dependent, or cost-doomed curve earned
the same boost as a robust one — as long as its *gross* mean was positive.
P12.5 closes that gap with the audits' formula
(`docs/FREQTRADE_REVIEW.md` F25, `docs/BACKTRADER_REVIEW.md` BT12):

> **`Score = E_R × Stability × SampleConfidence − DD/complexity penalties`**

> **"How much of this setup's observed edge should the engine trust to
> repeat — in this regime, at these costs?"**

## 2. What shipped

### A. `data/strategy_score.py` — the pure score

`strategy_score(rows, *, plan_type, regime, setup_rows, min_decided,
criteria, step)` → one dict with `score` (0–100), `band`, `weights`,
`components`, `expectancy_net`, `n`, `n_eff`. Four multiplicative
components, each 0–100, composited as a **weighted geometric mean** — the
"×" in the audits' formula is literal: a zero on any axis zeroes the score
(no edge × anything = no strategy):

| component | weight | what it measures |
|---|---|---:|---|
| **e_r** | 35% | P12.4's `edge_score` verbatim — E_net vs the bar, shape-discounted on WR/PF misses |
| **sample_quality** | 35% | **P12.4's `backtest_quality_score()` in full** — curve robustness (top-5 concentration / drawdown / chronological segments) × sample confidence (N_eff + CI95) — read, never reimplemented |
| **regime_fit** | 15% | base key: sample-weighted fraction of regimes with positive E_net (a one-regime edge is real, but the base key can't know which regime is next); `plan_type::regime` key: the regime's E_net vs the setup's all-regime E_net (100 = ≥1.5× stronger here, 66.7 = average, 0 = no edge in this regime) |
| **execution** | 15% | share of the gross edge surviving the P12.6 cost model: `1 − avg_cost_r / avg_gross_r` (modelled fees+spread+funding until micro-live records real fills) |

Bands: ≥ 80 `robust` · ≥ 60 `acceptable` · ≥ 40 `borderline` · else `fragile`.
Empty books degrade to `score: None` with a reason (silence is not an edge).

### B. The calibrator's new trust dial

`multiplier_from_score(expectancy, strategy_score_value, …)`:

    mult = clamp(1 + E_gross × gain × trust, min, max)
    trust = clamp(score / 50, 0.6, 1.5)

- score 50 → trust 1.0 → the **pre-P12.5 formula exactly**;
- a robust, well-sampled, regime-fit, cost-surviving setup is trusted up
  to 1.5×;
- a fragile or net-negative book is shrunk to the 0.6 floor — its
  boost/dampening is shrunk, not celebrated;
- the sign anchor stays the observed gross expectancy, so a losing setup
  is always dampened (or filtered), never boosted.

### C. One computation, many surfaces (invariant #10)

The score is computed once in `build_profile` and persisted; every surface
reads the same stored block:

- `python main.py learn` — `describe()` prints `score N/100 band` per
  entry; `--json` dumps the full profile including `strategy_components`.
- `GET /api/learning` — calibration entries carry `strategy_score` /
  `strategy_band`.
- Dashboard `LEARNING` card — new band-coloured `Score` column + a P12.5
  legend line.
