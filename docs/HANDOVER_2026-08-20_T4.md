# Handover — 2026-08-20 · v2.52.0 — T4 (part 1): honest sizing, live bottom tabs, skeletons

**The terminal no longer invents money.** Three long-standing polish items
from `ROADMAP.md` §T4 are now shipped: the trade ticket sizes and prices
fees from the *real* account balance and the *real* cost model instead of a
fabricated $100k default; the bottom tabs re-fetch on every switch instead
of caching one stale paint forever; and slow panels show loading skeletons
instead of blank space.

**No new trading capability.** One read-only endpoint, advisory UI, and
client-side arithmetic only. No threshold moved, no exchange-order path, no
new permission.

## What shipped

### Backend (`web/app.py`)

- **`GET /api/ticket/meta?symbol=`** — the honest inputs for the ticket:
  - `account_balance` / `account_configured` from `ACCOUNT_BALANCE` (0 and
    `false` when unset — the UI must then show **—**, never a default);
  - the per-symbol cost model via `data.costs.cost_model_for_symbol`:
    `taker_fee_pct` / `spot_fee_pct` / `half_spread_pct` / `slip_pct` /
    `funding_rate_8h` / `holding_hours`, plus a precomputed
    `round_trip_cost_pct = 2·fee + 2·spread + 2·slip`;
  - gold (XAU*) resolves to the spot model (commission-based, **no
    funding**), everything else to the crypto-perp model — the same resolver
    `data.costs.calculate_trade_cost` uses, so the ticket preview and the
    desk's cost doctrine cannot disagree.

### Frontend (served `web/app.py` script; `web/static/terminal_newjs.js` kept in sync)

- **Honest ticket sizing** (`recalcTicket`). Risk dollars = `account × risk%`,
  units = risk ÷ stop distance, only when an account balance exists;
  otherwise **—** with a "set ACCOUNT_BALANCE" hint. The `$100k` `|| 100000`
  fabrication and the hand-rolled `0.1%` fee are gone.
- **Honest fees** — from `round_trip_cost_pct`: dollar figure when the ticket
  is sized, the % always (`0.14% round-trip`).
- **`loadTicketMeta()`** replaces the dead `loadRiskAccount()` (which read a
  field `/api/risk` never returned, so the $100k fallback was *always*
  live). Fetches on terminal load and on symbol change (`setSymbol`).
- **Bottom tabs re-fetch** — `_bottomLoaded` removed; `renderBottomTab` always
  fetches and `switchBottomTab` tracks `_bottomTab`. `alerts` keeps its static
  push-button content (never overwritten with a skeleton). The 60 s refresh
  re-renders the visible positions tab.
- **Loading skeletons** — `.skel`/`.skel-row` shimmer CSS; `_skeleton(n)`
  paints rows for the watchlist and each bottom tab while its fetch is in
  flight.

## Honest boundaries (unchanged)

- The fee/size numbers are a **preview**; the authoritative gate read and the
  paper enrollment still happen server-side at `POST /api/terminal/confirm`
  (T3), which never uses the client's size or fee estimate.
- `ACCOUNT_BALANCE` is the operator's own declared balance for sizing — the
  terminal still cannot and does not place an order.
- No real browser in this sandbox — proven with the node harness, the Flask
  test client, and `node --check` on the served script.
