## What shipped

P13.6 closes the compare-ladder item from the P13 edge-validation spec
(`docs/P13_EDGE_VALIDATION_SPEC.md` §3.6). `edge-validate` can now pair the
decisive-window verdict with the **canonical live paper book** in one report,
so the owner sees the honest degradation ladder:

```
Backtest (whole walk) → OOS + recent (decisive) → Paper (canonical live)
```

instead of three disconnected numbers. Every rung is **net of costs** and an
empty rung renders as `n/a` — never an invented number.

### Code

- **`engine/edge_validation.py`**
  - `paper_stats_from_rows(rows)` — aggregates the canonical live paper book
    (`SignalDB.live_book_rows()`: decided TP_HIT/STOP_LOSS, non-simulator,
    canonical-live) into public stats; `rr_net` with the P12.6 gross
    fallback; empty dict when there is no paper evidence yet.
  - `compare_ladder(report, paper_stats)` — composes the three rungs
    (backtest = whole-walk graded plans, oos = `edge.overall`, paper =
    canonical live book) plus an honest one-line note: degradation when
    paper < OOS, hold when paper ≥ OOS, "keep grinding P11" when the paper
    rung is empty, "OOS too thin" when the decisive rung is empty.
  - `format_compare_ladder(report)` — human-readable ladder table (n/a rows
    for empty rungs).
  - `edge_validate_report(..., paper_rows=None)` — when `paper_rows` is
    provided the result carries `backtest_stats` + `ladder`. Without it the
    output is byte-identical to v2.57.0 (the P13.5 promise holds).
- **`main.py`** — `edge-validate` gains `--ladder`: opens `SignalDB`, reads
  `db.live_book_rows()` (empty DB → empty rows → honest n/a rung), passes
  them to the report, and prints the ladder block after the verdict. JSON
  output includes the `ladder` object under the top-level key.

### CLI usage

```bash
# Verdict + compare ladder (paper book read from the canonical DB)
python main.py edge-validate --source store --tf 15m --bars 2000 --ladder

# With Monte-Carlo floor (P13.5) + ladder (P13.6) in one report
python main.py edge-validate --source store --tf 15m --bars 2000 --monte --ladder

# JSON (ladder block under the "ladder" key)
python main.py edge-validate --source store --tf 15m --bars 2000 --ladder --json
```

### What did NOT change

- The graduation gate and default `python main.py backtest` remain on
  `EXECUTION_MODEL="none"`.
- `--ladder` is off by default — existing invocations are byte-identical.
- No threshold moved, no order placed, no exchange-order path.
- `edge-validate` is still read-only; the ladder is a comparison surface, it
  never approves anything.
- No new endpoint — the CLI composes the existing `live_book_rows` surface;
  the dashboard can compose the same data from `/api/v1` when surfaced.

## Ladder note rules

1. OOS rung empty → "OOS rung empty — the decisive-window sample is too
   thin; the ladder cannot show an honest degradation yet".
2. Paper rung empty → "paper rung empty — no decided canonical live trades
   yet; simulator rows never count (P12.13). Keep grinding P11."
3. Paper expectancy < OOS → explicit Δ in R, named as expected degradation
   as costs, slippage and human decisions enter the ladder.
4. Paper ≥ OOS → "no degradation measured on this book".

## P13.1 monotonicity (also shipped this session)

(never better)" is closed with two assertion tests on **real graded output**
