## 1. Finding — graduation compliance is still polluted

P12.13 isolated *performance* evidence by source: `data.simulator.paper_progress()`
now reads canonical live rows only (`COALESCE(source_key,'') = ''`). The
**discipline** criterion was not isolated. Every graduation surface still does:

```python
j = violation_rate(db)                                   # brain/journal.py:99
compliance = 1.0 - j["violation_rate"] if ... else None  # 4 duplicated sites
g = graduation_status(progress, compliance=compliance)
```

and `violation_rate()` delegates to `SignalDB.journal_stats()`
(`data/database.py:497`), which is:

```sql
SELECT * FROM journal_entries      -- every row, no join, no provenance filter
```
```python
violations = sum(1 for e in entries if e.get("followed_rules") == 0)
violation_rate = violations / n
```

Consequences, all four confirmed by execution (§2):

| # | Failure mode | Why |
|---|---|---|
| A | Simulator journals satisfy the 90% criterion | walk-forward samples auto-write `followed_rules=1`; nothing filters `sim_key IS NOT NULL` |
| B | Non-canonical research journals move canonical compliance | `journal_entries` is never joined to `paper_trades.source_key` |
| C | `followed_rules IS NULL` scores as compliant | only `== 0` counts as a violation; NULL is silently a pass |
| D | Missing journals fail **open** | the denominator is *journal rows*, not *decided real trades*; an unjournaled book is invisible |

Net effect: the 90% discipline criterion can pass **without a real, fully
journaled canonical live paper book** — the exact class of bug P12.13 fixed on
the performance side.

## 3. Implementation contract (P12.14 / v2.23.2)

One central computation, built in `brain/journal.py`
(`graduation_discipline(db)`, backed by `SignalDB.discipline_rows()`), with
`violation_rate()` untouched for the general journal report.

### 3.1 Eligible population

A decided **real canonical live paper** trade:

```sql
SELECT p.id, j.followed_rules
  FROM paper_trades p
  LEFT JOIN journal_entries j ON j.scan_id = p.scan_id
 WHERE p.outcome IN ('TP_HIT','STOP_LOSS')     -- decided only
   AND p.sim_key IS NULL                        -- exclude simulator samples
   AND COALESCE(p.source_key,'') = ?            -- LIVE_SOURCE_KEY ('' = binance spot)
```

* `COALESCE(..., '')` deliberately keeps **legacy NULL** source rows: that is the
  same canonical Binance-spot history (identical convention to `paper_progress()`).
* Guard for pre-migration DBs where `sim_key` / `source_key` columns are absent
  (`data/database.py` already uses a `cols` introspection pattern — reuse it).
* `backtest_results` rows are **not** eligible: discipline is about executed
  paper trades a human was supposed to journal.

### 3.2 Journaled / violation classification

* journaled ⇔ `followed_rules IN (0, 1)`
* violation ⇔ `followed_rules = 0`
* compliant ⇔ `followed_rules = 1`
* `followed_rules IS NULL` **or** no journal row ⇒ *missing journal*, counted in
  the denominator, never in the numerator.

### 3.3 Payload

```python
{
  "eligible": int,          # decided canonical real paper trades
  "journaled": int,         # followed_rules in (0,1)
  "missing_journals": int,  # eligible - journaled
  "violations": int,        # followed_rules == 0
  "compliant": int,         # followed_rules == 1
  "compliance": float|None, # compliant / eligible  — None when eligible == 0
  "source_key": "",         # canonical live, echoed for auditability
}
```

Fail-closed algebra: `compliance = compliant / eligible` (**not**
`compliant / journaled`). `eligible == 0 → compliance = None`, which
`graduation_status()` already treats as unproven, never a pass.

functions covers the desk, API, dashboard and MCP, but verify the dashboard
graduation card renders `missing_journals`.

### 3.6 Open design decision (decide explicitly, then document)

Should eligibility be restricted to the **primary plan family**
(`primary_plan_types()`), as the sample criterion is? **Recommendation: no** —
discipline is a property of the trader across the whole canonical real paper
book, and a plan filter would let an undisciplined non-primary book hide.
Whichever way it goes, state it in the docstring and cover it with a test.

## 4. Required regressions (new tests)

1. Simulator-only journals ⇒ `eligible == 0`, `compliance is None`, graduation
   `met["compliance"] is False` (case A).
2. Non-canonical journals cannot move canonical compliance (case B).
3. `followed_rules=None` counts as a missing journal, not a pass (case C).
4. Missing journals fail closed: 30 eligible / 1 journaled ⇒ `≈0.033` (case D).
5. Legacy `source_key IS NULL` canonical rows remain **included**.
6. Fully journaled canonical real book computes exactly as today (case E, 0.9).
7. Surface parity: `main.py simulator --json`, `agent ask`,
   `graduation_report()`, and `desk_status()` return an identical discipline
   payload for one fixture DB.

Target: **≥ 733 passed / 1 skipped** (726 baseline + the seven above).
