## Delivered

- `ops/release.py`: sorted SHA-256 artifact records; closed `stable|beta`
  channel vocabulary; API compatibility/release manifest; SPDX 2.3 SBOM;
  dependency/license inventory; recursive diagnostics redaction; signing
  readiness that exposes names/booleans but never values.
- `packaging/build_release.py`: one command writes `release.json`,
  `SHA256SUMS`, `sky.spdx.json` and `dependencies.json` around built outputs.
  Metadata cannot claim an artifact is signed without a verifier record.
- `python main.py hub diagnostics`: mode-0600 support tarball containing only
  `diagnostics.json`; DB, market store, env, raw logs and secrets excluded.
- `ci/release.workflow.yml`: reviewed GitHub Actions specification for the
  Ubuntu/Windows contract matrix, API contract, direct Debian build +
  clean-runner install/setup/backup/remove smoke, metadata/SBOM artifact and
  `pip-audit`. PR jobs use no signing secrets. Arena's GitHub App cannot write
  `.github/workflows`; a repo admin must copy it there to activate it.
- Fixed two P19 package defects exposed by the smoke gate:
  `${misc:Depends}` was copied literally by the direct builder, producing an
  invalid binary control file; the package copied source without creating its
  Python runtime, so `/usr/bin/sky` failed on a clean host; and dpkg uninstall
  left the generated venv/caches under `/opt/sky`. The beta post-install now
  creates the package venv and post-remove cleans only the application tree
  while retaining `/etc/sky` + `/var/lib/sky` unless purged. Stable promotion still requires a
  reviewed pinned wheelhouse; network-resolved beta dependencies are not a
  reproducibility claim.
- `docs/RELEASE_OPERATIONS.md`: trust boundary, channels, promotion sequence,
  platform verification, private diagnostics, support and incident paths for
  Hub offline, stale data, locked/corrupt DB, disk full, expired certificate,
  failed migration, lost phone and rollback.
- `tests/test_release_ops.py`: 10 release/privacy/workflow regressions.

## Honest limits

- This is **P22.1, not P22 completion**.
- No signing credential exists in the repository or PR CI. No signed `.deb`,
  Debian repository, `.exe`, `.msix`, `.apk` or `.aab` was produced.
- P20/P21 contain executable client contracts and packaging recipes, not native
  projects. Their real build/lint/instrumented jobs cannot exist until P22.2
  creates those projects.
- Linux CI cannot claim a clean physical Windows/Android install, notification,
  biometric, upgrade or rollback drill.
- Packaging does not prove edge, move a threshold or unlock micro-live.
