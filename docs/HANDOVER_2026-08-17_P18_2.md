# P18.2 — Stable application API (`/api/v1`)

**Shipped:** 2026-08-17 · branch `arena/01a00eac-sky` · version **2.30.0**
**Previous:** P18.1 authentication & authorization (v2.29.2, PR #47)
**Next code:** P18.3 persisted background jobs + SSE, then P18.4 PWA.

---

## 1. What the roadmap asked for

From `ROADMAP.md` §P18.2:

> - Versioned `/api/v1` contract for dashboard and companion clients.
> - One response envelope and typed error codes; no client parses terminal text.
> - Compatibility policy: clients can detect minimum/maximum server versions.
> - Idempotency keys for human mutation requests so retries cannot duplicate an action.
> - Device registration/revocation and a visible connected-device list.
>
> **Done when:** web, Windows, and Android can use one documented contract and
> an old client receives a clear upgrade message instead of corrupt behavior.

All five are implemented and tested. The "done when" is met for the contract
itself; the Windows and Android clients are P20/P21 and do not exist yet.

## 2. What was built

### `web/api_v1.py` (new, stdlib only)

The contract, expressed as data and pure functions so it can be tested without
a running server:

| Piece | Purpose |
|---|---|
| `envelope_ok` / `envelope_error` | The single response shape. |
| `ErrorCode` | Closed vocabulary of machine-readable codes. |
| `code_for_status` | Maps a legacy handler's HTTP status onto a typed code. |
| `version_info` / `check_client_version` | Compatibility negotiation. |
| `IdempotencyStore` | Persisted replay cache for human mutations. |
| `ROUTES` / `NATIVE_ROUTES` / `route_catalog` | The route table, published at `/api/v1/routes`. |

### `web/app.py` integration

* Delegating routes are generated from `ROUTES`. Each calls the **same legacy
  view function** the dashboard calls and re-renders the answer in the v1
  envelope. This is deliberate: v1 must not become a divergent second
  implementation with its own bugs and its own security review.
* v1-native routes (`/version`, `/routes`, `/me`, `/devices`,
  `/devices/revoke`, `/audit`) surface P18.1 state as a stable contract.
* The P18.1 `before_request` gate now renders refusals in whichever contract
  the caller used, and reads the required role for v1 mutations from the
  declared route table.

### `data/database.py`

One new table, `idempotency_keys`, created idempotently like the P18.1 tables.

## 3. The four promises a client may rely on

### 3.1 One envelope

```json
{
  "ok": true,
  "data": { "...": "payload" },
  "error": null,
  "meta": {"api_version": 1, "server_version": "2.30.0",
           "request_id": "a1b2c3…", "ts": 1786953426072}
}
```

Failure is the same shape with `data: null` and
`error: {code, message, details}`. There is no third shape — pinned by
`_assert_envelope` running over every read endpoint.

**Legacy `/api/*` is untouched** and keeps its historical shapes, so the
shipped dashboard does not break mid-migration. A regression test asserts
`/api/pending` still returns a bare payload with no `meta`.

### 3.2 Typed error codes

Clients branch on `error.code`. `error.message` is human-facing and may be
reworded at any time without that being a breaking change.

Notable mappings, chosen so a client can render the *right* thing:

| Situation | Code | HTTP |
|---|---|---|
| Risk gate refuses an approval | `RISK_GATE_CLOSED` (with `details.blocked_by`) | 409 |
| Illegal lifecycle transition (usually a retried decision) | `LIFECYCLE_INVALID` | 400 |
| Viewer attempts an operator action | `FORBIDDEN` (with `details.required_role`) | 403 |
| Key reused with a different body | `IDEMPOTENCY_KEY_REUSED` | 409 |
| Client outside the supported range | `CLIENT_TOO_OLD` / `CLIENT_TOO_NEW` | 400 |

A closed risk gate is deliberately **not** a generic bad-request: it is the
desk saying no on purpose, and the client should show the reasons.

### 3.3 Compatibility

`GET /api/v1/version` is **public** — a client must discover the range before
it can authenticate. It reports `min_client_version` / `max_client_version`
and the header names to use.

The version check runs **before authentication**. This matters: if an
out-of-range client were answered with 401, the app would tell the user their
password was wrong, which is exactly the "corrupt behavior" the roadmap says
to avoid. Pinned by `test_version_check_precedes_authentication`.

`version_info()` also advertises `live_exchange_execution: false`, so a
companion client can discover that SKY cannot place an order rather than
shipping a Trade button that can never work.

### 3.4 Idempotency

Applies to `/review`, `/journal`, `/paper/run`, `/trader-state`.

```
POST /api/v1/review
Idempotency-Key: 8f14e45f-ea0f-4f0e-9a1b-2c3d4e5f6a7b
```

* First call executes; the **rendered response** is stored.
* A retry with the same key + same body replays that response byte-identically,
  with `meta.idempotent_replay: true`. No re-execution.
* Same key + **different** body → `IDEMPOTENCY_KEY_REUSED` (409). Returning the
  cached result for a different request would hide a real client bug, and
  could hide a wrong trade decision.
* A too-short key is **refused**, not ignored: a client that believes it has
  retry safety and does not is the dangerous case.
* Keys are scoped per `(key, user_id, endpoint)` with a 24h TTL, and persist
  in SQLite so a retry survives a server restart — the Android client
  reconnecting after a crash is the case this exists for.
* If the cache itself is unavailable the request still executes (degraded to
  non-idempotent) rather than failing the user's action.

**Proof it is real, not decorative:** `test_only_one_decision_is_recorded_for_a_replayed_key`
fires four identical review calls and asserts exactly **one** row in
`decisions`. `test_without_a_key_the_retry_is_not_protected` is the control —
the same retry without a key hits `LIFECYCLE_INVALID`, proving the replay is
the key working rather than the endpoint being harmlessly repeatable.

## 4. Security — inherited, never re-implemented

The P18.1 `before_request` gate covers `/api/`, which includes `/api/v1/`.
v1 therefore gets authentication, role checks and CSRF from the *same* code
path; only the rendering of refusals changed.

Two additions:

* **Roles come from the declared route table.** `_required_role()` reads
  `ROUTES`/`NATIVE_ROUTES`, so the published catalog and the enforced policy
  cannot drift apart.
* **Undeclared mutating routes default to `operator`** — forgetting to declare
  a new route fails closed, not open.

`tests/test_api_v1.py` re-asserts every P18.1 invariant against the new
surface, because a new API is exactly where an authorization hole gets
introduced:

| Invariant | Test |
|---|---|
| Unauthenticated cannot read private state | `test_unauthenticated_cannot_read_private_state` |
| Unauthenticated cannot mutate | `test_unauthenticated_cannot_mutate` |
| Viewer cannot approve/reject/close | `test_viewer_token_cannot_approve_reject_or_close` |
| Viewer cannot mint an operator token (escalation) | `test_viewer_token_cannot_mint_or_revoke_devices` |
| Viewer cannot read the audit log | `test_viewer_cannot_read_the_audit_log` |
| **Operator cannot bypass the risk gate** | `test_operator_cannot_bypass_the_risk_gate` |
| Cookie mutations require CSRF | `test_cookie_mutations_require_csrf` |
| Revoked device token stops working | `test_revoked_device_token_is_refused` |

Force-approve remains disabled unless `SKY_ALLOW_FORCE_APPROVE=1`, through v1
as through the legacy path.

## 5. A bug found and fixed while building

`_unwrap` originally preferred the response object's `status_code`. But
legacy handlers return `jsonify(...), 400` — and a `jsonify` Response carries
the **default 200**, with the real status living in the tuple. Every legacy
4xx would have been re-rendered as a 200-shaped `INTERNAL` error: a client
would have seen "server error" where the truth was "you sent a bad decision
value". The tuple's status now wins. This is why the typed-code tests assert
the *status* as well as the code.

## 6. Verification

```bash
DEMO_MODE=1 python -m pytest tests/test_api_v1.py -q        # 59 passed
DEMO_MODE=1 python -m pytest -q                             # 982 passed / 1 skipped
```

Three failures are **pre-existing and environmental**, unchanged from the
baseline measured before this work: `test_agent.py::test_health_report_ok` and
two `test_mcp_server.py` tests fail because the `mcp` package is not installed
and the sandbox has no outbound network.

Also verified over real HTTP against a running server (not only the test
client): unauthenticated read → 401; public `/api/v1/version`; cookie login →
device registration → that device reading with a bearer token and **no**
cookie; and that same viewer-scoped device being refused an approval with
`FORBIDDEN`.

### Not verified

* **No real companion client exists yet.** The contract is proven against
  `curl` and the test client. P20/P21 will be the first true consumers, and
  the first honest test of whether this contract is pleasant to build against.
* The dashboard UI was verified through the repo's `jsdom`/node harness
  (`tests/test_workstation_js.py`), not by a human looking at a browser — no
  browser is installable in this sandbox.
* `min_client_version == max_client_version == 1` today, so the *upgrade*
  paths are exercised by tests with synthetic version headers rather than by
  a genuinely old client.

## 7. What this does NOT do — read before P18.3

* **It adds no capability.** Every delegating route calls an existing handler.
  A test (`test_v1_adds_no_route_the_legacy_api_did_not_have`) enforces that
  every v1 route maps to a legacy route that already existed.
* **It moves no threshold.** The 100 backtest / 20 paper / positive-expectancy
  graduation bar is untouched. Micro-live remains blocked.
* **It adds no exchange-order path.** There is still no way to place an order
  anywhere in SKY, and `/api/v1/version` says so out loud.
* **Long jobs are still blocking POSTs.** `backfill`, `backtest` and
  `simulator` still run inside one request behind a timeout. That is exactly
  **P18.3** (persisted job queue + SSE) and is the next code.

## 8. Suggested next steps

1. **P18.3** — persisted job queue + SSE, so closing a browser does not kill a
   job and duplicate clicks do not start duplicate runs. The idempotency
   machinery built here is the natural deduplication key for job submission;
   reuse `IdempotencyStore` rather than inventing a second mechanism.
2. When P20/P21 begin, bump `MAX_CLIENT_VERSION` only for genuinely breaking
   changes, and raise `MIN_CLIENT_VERSION` with real reluctance — every raise
   strands installed apps.
3. Migrate the dashboard's own `fetch` calls to `/api/v1` incrementally. There
   is no rush: the legacy surface is tested and pinned, and a big-bang
   front-end migration would risk the workstation for no user-visible gain.
