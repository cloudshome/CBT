# Handover — 2026-08-21 · v2.54.0 — T5: Home screen & onboarding

**The post-login landing is now a concise command dashboard, not a wall of
modules.** The five remaining `ROADMAP.md` §12 items for the Home screen are
shipped: continue-last-market, the eight-item board (risk gate, data
freshness, open positions, today's P&L, journal tasks, evidence progress,
focus/alerts) and the **Open Trading Terminal** primary button — plus first-run
onboarding that points at the paper loop, never at a CLI.

**No new capability.** Presentation layer only: the board is a pure, read-only
composition of the existing `/api/risk`, `/api/readiness`, `/api/trades` and
`/api/loop-health` payloads. **Zero new endpoints, zero new permissions, no
threshold moved, no exchange-order path.** The graduation bar (E ≥ +0.50R,
WR > 55%, PF ≥ 1.5, compliance ≥ 90%, ≥100 backtest + ≥20 paper per primary
setup) is shown, not touched.

## What shipped

### Home (`view-home`, first nav area)

- **Landing behaviour**: no `#hash` and no remembered view → land on **Home**.
  A remembered view or an explicit `#trade`/`#markets`/… hash still wins, so a
  returning user who lives in the terminal keeps landing there.
- **Hero**: time-of-day greeting with the signed-in user, the honest one-liner
  ("the machine proposes, you approve, the runner simulates — no real exchange
  order exists"), a **Continue ‹symbol · timeframe›** button that restores the
  remembered market (validated against what the server still offers, same rule
  as T4), and the **Open Trading Terminal ⟶** primary button.
- **The board** (7 concise cards, not every module):
  - **Risk gate** — `OPEN`/`BLOCKED` straight off `/api/risk`; when blocked it
    prints the real `blocked_by` reasons (first two + "· +N more"). Links to
    the risk centre.
  - **Data freshness** — `/api/readiness` level + headline + the **data**
    pillar line (e.g. "no stored market history yet", "3 series fresh",
    quarantine when P10.5 trips). Links to System.
  - **Open positions** — count + up to three rows (symbol · action · live R in
    R-multiples, green/red) off `/api/trades`; honest "Nothing running — a
    paper ticket is one click away" empty state.
  - **Today's P&L** — net-%-of-equity today and this week, decided-trade
    count, and the **hard daily limit** — straight off
    `gate.details.daily_weekly` (live book, net of costs, P12.18). Tripped
    daily/weekly limits print the amber warning lines. Nothing is recomputed
    client-side.
  - **Journal tasks** — missing journals (**journal-first hold is named**:
    "the next confirm holds until these are written"), pending reviews, and
    the daily question "did I follow the system today?".
  - **Evidence progress** — criteria met x/4 (or `GRADUATION READY`), real
    paper `n`, the unmoved bar in plain text, and per primary-setup
    `paper n/target · backtest n/target` rows off `loop.graduation.by_setup`.
  - **Focus** — the desk's `advice.action` + headline from loop-health, and
    trader-state flags (`gate.flags`) with "clear the flag before any new
    trade" when set.
- **Honest states everywhere** — skeletons on first paint; every feed settles
  independently (`Promise.all` over per-feed try/catch), so a dead feed paints
  `⚠ could not load — ‹server error› retry` in its own card(s) while the rest
  of the board still renders. No silent blanks, no frozen board (T4 lesson).
- **Re-read every visit** — no one-shot cache; `navTo('home')` and the 60 s
  home interval re-fetch. Mutations: zero — the board only ever GETs.
- Mobile: hero stacks, the primary button goes full-width, the card grid
  collapses to one column (`≤760px`).

### Onboarding (`#homeOnboard`)

Shown **only for a fresh desk** (no real paper trades, no open positions, no
pending reviews — and not previously dismissed): "Welcome to SKY — start your
paper loop" with five numbered steps (open terminal → read the setup → prepare
the paper ticket → confirm paper-only → manage & journal) and the same primary
CTA. It names the paper-first contract explicitly and never mentions a command
line. Dismissal persists per browser (`sky.home.hideIntro`); every read is
try/catch-wrapped so a private-mode browser still runs.

## Honest boundaries (unchanged)

- The board is a *reader*: it never approves, never confirms, never mutates.
  `posts === 0` is asserted in the JS tests.
- The onboarding heuristic is evidence-based and re-appears only for a truly
  fresh desk; it never claims samples that do not exist.
- **No real browser in this sandbox** — proven with the node/jsdom-style
  harness, the Flask test client, `curl` against a running dev server, and
  `node --check` on the served script. Visual QA of hero/onboarding/mobile
  stacking on a real browser remains part of the open T1–T6 QA item (with the
  T4 drag/collapse/drawer gestures and the T3 loop).
