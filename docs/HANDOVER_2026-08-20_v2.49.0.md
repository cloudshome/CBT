## What shipped

SKY's web dashboard is now a **professional Trade Terminal** — one screen with
a watchlist (left), a large chart (centre), a paper-trade ticket + AI panel
(right) and a tabbed trading panel (bottom). The roadmap
([`ROADMAP.md`](../ROADMAP.md)) has been rewritten around this vision: *one
professional trading platform, not a collection of Python functions and
separate dashboard cards*.

### The Trade Terminal (default view)

```
+---------------------------------------------------------------------------+
| SKY   BTCUSDT | 15m    feed | gate | positions | AI | refresh | account   |
+---------+--------------------------------------+-------------------------+
|WATCHLIST|  CHART (Lightweight Charts)          | ORDER PANEL (tabs)      |
| search  |  EMA/VWAP/BB/Levels/Zones/Plan/RSI   |  Ticket | Signal | Risk |
| prices  |  drawings, replay, live, multi-chart |  | Copilot              |
| 24h chg |  readings + levels + drawings strip  |  Buy/Sell, entry, SL,   |
| pos mini|                                      |  TP1-3, risk %, size,   |
|         |                                      |  R:R, fees, gate verdict|
+---------+--------------------------------------+-------------------------+
| Positions | Pending plans | Trade history | Journal | Alerts | Evidence | Background |
+---------------------------------------------------------------------------+
```

- **Six-area navigation** replaces the 16-tab bar: **Trade, Markets,
  Portfolio, Journal, Evidence, System** — compact inline SVG icons, no emojis
  in primary navigation.
- **Trade** = the terminal (default). The other five areas group the existing
  panels: Markets (overview/market/intelligence), Portfolio
  (trades/manage/risk/weekly), Journal, Evidence (evidence/learn), System
  (connections/commands/modules/system/agent). Modules and Command Center are
  now under System, not dominating the screen.
- **Trade ticket** — real-exchange-style paper ticket clearly marked
  *PAPER — NO REAL ORDER WILL BE SENT*: Buy/Sell, Market/Limit/Conditional,
  entry, stop loss, TP1/TP2/TP3, risk %, position size (auto from risk),
  planned R:R, estimated fees, risk-gate verdict (open/blocked with reasons),
  and a Confirm button that stays disabled while blocked. The ticket is
  prefilled from the latest scan payload.
- **AI Copilot** — a persistent right-side drawer (✦ button in the top bar)
  plus a Copilot tab in the order panel. Eight quick-action buttons (Explain
  chart, Why blocked?, Review signal, Open position, Invalidation, Today,
  Journal, Graduation) and free chat through the existing `POST /api/ask`
  with automatic context injection (symbol, timeframe, signal, desk decision,
  risk-gate reasons, MTF, sentiment). The response is split into labelled
  sections when the desk returns structured text.
- **Bottom trading panel** — seven tabs: Open positions (with live R and
  click-through to the Trade Manager), Pending plans (approve/reject inline),
  Trade history, Journal (entries + compliance), Alerts (push controls),
  Strategy evidence (per-setup E_net/proven), Background (jobs).
- **Top-bar status chips** — feed freshness (from `/api/readiness`), risk-gate
  status (from `/api/risk`), open-position count (from `/api/paper`).
- **Professional visual language** — flat dark background `#0b0e14`, thin
  1px borders, compact typography, green/red reserved for direction & P&L,
  amber for warnings, cyan for SKY actions, dense but calm.

### What did not change (safety & compatibility)

- Every server endpoint, the risk gate, the graduation bar, auth/roles/CSRF,
  the `/api/v1` contract, jobs/SSE, PWA/offline, and all trading logic are
  untouched. The terminal is a **presentation layer** over the existing API.
- The paper ticket is advisory: it validates and sizes, and its Confirm flow
  routes through the existing approval queue (`/api/pending` →
  Approve/Reject) — it cannot bypass the gate and cannot send a real order.
- The legacy dashboard shell is preserved intact as the non-Trade views
  (grouped), so every previous function (Command Center, Modules, Hub role,
  research agent, weekly review, practice mode, multi-chart, replay, live
  stream, drawings, journal forms) remains reachable.
- `web/static/terminal_head.html` and `web/static/terminal_newjs.js` are the
  new template sources; `web/app.py` inlines them (splice script was
  throwaway; see "How it was built").

## How it was built (for the next session)

`web/app.py` still contains one giant `HTML = """…"""` template (the tests
extract it and run the JS in jsdom). The current template is assembled from:
1. `web/static/terminal_head.html` — CSS + top bar + 6-area nav + the
   terminal markup + AI drawer + modals.
2. The legacy `<div class="shell">` extracted verbatim from the previous
   template (minus the old chart tabpanel, whose elements now live in the
   terminal; the ✍ PRACTICE card was preserved and appended).
3. The full previous inline `<script>` (all existing JS) followed by
   `web/static/terminal_newjs.js` (terminal behaviour).

**To regenerate after editing the head/newjs:** restore `web/app.py` from git
(`git checkout web/app.py`), then run the splice — the one-shot script used
for this session is not committed (it is a build tool, not product code), so
either re-derive it from this doc or edit `terminal_head.html` /
`terminal_newjs.js` and re-splice with an equivalent script. **Never run the
splice twice without restoring web/app.py first** (it would double-apply).
